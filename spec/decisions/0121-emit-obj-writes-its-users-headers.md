# ADR 0121 — `--emit obj` writes its user's headers

- Status: **Accepted** by the owner, 2026-11-13 ("Fix those new gaps too"), implemented on branch `fix/gaps2-d`; released in ceesafec
  0.42.0. Raised by the book's authors (gaps2 D7): a freestanding environment defines `ceesafe_panic`, whose
  types are in `ceesafe/rt.h`, and `--emit obj` wrote no header, so the reader ran a second `ceesafec build --emit c`
  only to get it.
- Scope: the driver (`src/host/build.cee`, `writeHostHeaders`); `spec/profiles.md` §4.3, `spec/tooling.md` §8.3;
  `guide/kernel.md`; `tools/embed_check.py`, `tools/freestanding_check.py`. It amends ADR 0088 §2.1 ("`--emit obj`
  stays as it is"). No change to the language, the libraries, the runtime or the generated C.

## 1. Context

`--emit lib` writes the host's headers beside the archive: `ceesafe/embed.h` and the exports header (ADR 0088 §2.1).
`--emit obj` was left as 0.27.0 had it, an object alone. But an object has a user too, and its C needs:

- in a freestanding build, `ceesafe/rt.h`: the environment defines `void ceesafe_panic(cee_panic_kind, cee_loc)`
  (profiles.md §4.2), and both types are declared there. `rt.h` includes `foreign.h` and `embed.h` beside it;
- the exports header, to call the program's `@export` functions with their checked prototypes;
- `ceesafe/embed.h`, for `ceesafe_init` and `ceesafe_shutdown` when the host's `main` is not CeeSafe's.

All of them came only from `--emit c`, a second build whose headers nothing ties to the object.

## 2. Decision

`--emit obj` writes headers beside its object, after the object is made:

- `ceesafe/embed.h` and, when the program has exports, the exports header under its `--exports-header` name: what
  `--emit lib` writes, in the same places (`-o build/driver.o` gives `build/ceesafe/embed.h`).
- In a freestanding build also `ceesafe/rt.h` and `ceesafe/foreign.h`. A hosted build's `rt.h` is not written: a
  hosted object's user defines nothing of the runtime's.
- Each starts with `/* Generated by ceesafec`, and replaces a file that starts so.
- **A file that does not start so is left as it is**: ceesafec prints one line on standard error (`ceesafec:
  --emit obj: left '<path>' as it is: ceesafec did not write it …`) and the build succeeds. `--emit lib` fails
  there; `--emit obj` does not, because a build set up before this ADR, when the object came alone, may keep a
  header of its own at such a path, and it must go on building.

Rejected: a flag to ask for the headers (the object is not usable from C without them, so they are not an option);
writing them only in a freestanding build (a hosted object's exports need their header as much).

## 3. Compatibility

An `--emit obj` build gains files beside its object: `ceesafe/` and, with exports, `ceesafe_exports.h`. Nothing that
was written changes, and no file of the user's is replaced.

## 4. Tests

- `tools/freestanding_check.py`: each freestanding program's C harness, which includes `ceesafe/rt.h`, is compiled
  with `-I` the object's directory, with no `--emit c` build (it stopped at the `#include` before).
- `tools/embed_check.py`: a hosted `--emit obj` writes `ceesafe/embed.h` alone under `ceesafe/` and the exports
  header; a user's `ceesafe_exports.h` there is left as it is, the build says so and succeeds.
